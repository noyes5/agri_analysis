⭐ AI 농산물 가격 예측 프로젝트 총정리

1단계: 데이터 소스 확보 (Data Sourcing)

두 가지 서로 다른 성격의 데이터를 수집하는 체계를 만들었습니다.
과거 데이터: KAMIS(식품유통정보)에서 5년 치 토마토 가격을, 기상청 ASOS에서 5년 치 과거 날씨를 가져왔습니다.
미래 데이터: 기상청 단기예보 API를 통해 앞으로의 3일간 예보 데이터를 실시간으로 가져오는 파이프라인을 구축했습니다.

2단계: API 통신 및 보안 (API & Security)

가장 고비였던 Forbidden 에러를 해결하며 실무적인 기술을 익혔습니다.
인증 관리: secret.json을 통해 민감한 API 키를 분리 관리했습니다.
통신 기술: 공공데이터포털의 특수한 인증 방식(Encoding/Decoding) 문제를 unquote와 URL 직접 결합 방식으로 해결했습니다.

3단계: 데이터 정제 및 호환 (Data Preprocessing)

서로 모양이 다른 데이터를 머신러닝이 먹을 수 있는 요리로 만들었습니다.
단위 일치: 1시간 단위의 예보 데이터를 1일 단위 평균/최고/최저 기온으로 압축(Aggregation)했습니다.
인코딩: '서울' 같은 문자열을 LabelEncoder를 통해 숫자로 변환했습니다.
스케일링: RobustScaler를 사용하여 이상치(Outlier)에 강한 데이터셋을 만들었습니다.

4단계: 베이스라인 모델 비교 (Baseline Comparison)

머신러닝으로 가기 전, 전통적인 통계 모델들과 성능을 비교했습니다.
ARIMA / ETS: 과거의 추세만을 분석하는 모델들의 RMSE를 확인하여, 우리가 넘어야 할 목표치(Base)를 설정했습니다.

5단계: 머신러닝 학습 및 최적화 (ML Training)
최신 알고리즘 3종 세트를 투입해 최강의 모델을 뽑았습니다.
RandomForest / XGBoost / LightGBM: 세 모델을 동시에 학습시키고 RMSE(오차)가 가장 낮은 **최적의 모델(Best Model)**을 선정했습니다.
모델 저장: 학습된 두뇌를 .pkl 파일로 저장하여 언제든 다시 쓸 수 있게 만들었습니다.

6단계: 실시간 예측 (Inference)

마침내 완성된 모델에 '내일의 예보'를 입력하여 실제 가격을 도출했습니다.
학습된 데이터의 규격(Feature)과 똑같이 예보 데이터를 가공해 모델에 넣었고, 최종적으로 "내일 예상 가격"이라는 결과물을 얻었습니다.

웹 대시보드: Streamlit 같은 도구를 써서 멋진 그래프와 함께 가격을 보여주는 웹사이트를 만들 수도 있죠.

⭐ data column

1. weather
- tm (날짜) : 관측일. (예: 2023-07-03)
- stnNm (지점명) : 관측소 위치. (예: 서울, 안동, 장수)
- avgTa (평균기온) : 하루 평균 기온. 전반적인 생육 속도를 결정.
- maxTa / minTa (최고/최저기온) : --> 핵심 파생 변수 재료.
	- 두 값의 차이로 '일교차'를 구해서 과일의 당도 예측에 쓰거나, 봄철 minTa가 영하로 떨어지는 날을 세어 '냉해 피해 위험도' 계산 가능.
- sumRn (일강수량) : 하루 동안 온 비의 양(mm).
- avgRhm (평균상대습도) : 습도(%).
	- 기온과 결합해서 '병해충(탄저병, 역병 등) 발생 확률'을 예측하는 데 절대적인 영향을 미침.

2. kamis
- item_name (품목) : 작물의 큰 분류. (예: 사과, 배, 배추)
- kind_name (품종) : 작물의 세부 종류. (예: 사과 중에서도 '후지', '홍로')
	- 같은 사과라도 품종마다 출하 시기와 가격이 완전 달라서, 분석할 때는 특정 품종 하나를 고정하는 게 좋음.
- rank (등급) : 상품, 중품 등. (보통 시장의 표준 가격인 '상품' 등급을 기준으로 분석)
- unit (단위) : 거래 단위. (예: 10kg, 1kg) --> 주의: 과거 데이터와 최근 데이터의 기준 단위가 바뀌는 경우가 간혹 있으니 꼭 확인해야 해.
- dpr1 (당일가격) : 우리가 알고 싶은 그날의 도매가격(원).
- dpr2 ~ dpr4 (과거가격) : 1일 전, 1개월 전, 1년 전 가격.

⭐ data feature
* weather
- 비가 안온 날은 Null --> 0으로 결측치 전처리 필요
- 휴일이 없음 : 365일 전체 데이터를 나타냄

* kamis
- 주말과 공휴일은 '데이터 증발' : 도매시장은 주 5일(또는 6일) 장이기 때문에 빨간 날엔 데이터가 아예 생성되지 않음.
- 날짜 컬럼이 없음 : API 응답 결과 자체에 '며칠 자 데이터인지'가 안 적혀 나오기 때문에, 파이썬 반복문을 돌릴 때 df['날짜'] = dt 처럼 라벨링을 해줘야 함.
- '-' 기호 : 가격이 없거나, 집계가 안되는 경우에 0이 아닌 '-'표시가 됨 --> 전처리 필요

* 수집 기본 정보
분석 타겟: 토마토 (도매, '상품' 등급 기준)
공간적 범위: 서울 (기상청 108번 지점 날씨 데이터 적용)
시간적 범위: 2021-03-01 ~ 2026-02-28 (과거 5년 치)

* 전처리(Preprocessing) 규칙
병합 기준: 날짜(Date)를 기준으로 기상청(Left)과 KAMIS 데이터 병합.
결측치(NaN) 처리: 주말 및 공휴일로 인해 비어있는 가격 데이터는 직전 평일 가격으로 채우고(Forward Fill), 불가피한 맨 앞부분은 뒤의 가격을 끌어와(Backward Fill) 시계열의 단절을 완벽히 제거함.
타입 변환: 쉼표(,)가 포함된 문자열 가격 데이터를 순수 숫자(Numeric)로 변환하여 모델 연산이 가능하도록 조치.

* 추가된 주요 파생 변수 (Feature Engineering)
가격 추세 변수: 1일 전 가격, 3일/7일 이동평균 가격 (단기 가격 흐름 반영)
기상 누적 변수: 3일 누적 강수량, 3일 평균 기온 (농산물 생육에 미치는 누적 데미지/호재 반영)
기상 파생 변수: 일교차 (최고기온 - 최저기온)

* 예측 변수 동기화 : 시간 단위의 통일 (Aggregation)
과거 데이터(ASOS): 기상청에서 이미 '하루 단위'로 계산해서 주는 일일 요약본입니다. (1일 1행)
미래 예보(Forecast): API는 1시간 단위로 총 72시간 치의 데이터를 던져줍니다. (1일 24행)
정제 방법: 예보 데이터를 날짜별로 그룹화(groupby)하여, 24개의 기온 데이터를 평균 내거나 최댓값/최솟값을 뽑아 과거 데이터와 똑같은 '1일 1행' 구조로 압축했습니다.

⭐ merge 특징

반복문을 통한 누적 수집 (pd.concat): 기상청 API는 한 번에 며칠 치를 묶어서 주지만, KAMIS API는 딱 '그날 하루'치만 줌. 따라서 반복문(for)을 돌려서 매일매일의 표를 모은 다음, pd.concat으로 위아래로 길게 이어 붙여 하나의 거대한 가격 표를 생성

공통 기준점(Key) : KAMIS 데이터를 가져올 때 daily_df['날짜'] = dt라는 코드를 써서, 표 안에 강제로 '날짜' 컬럼을 밀어 넣음.

Left Join (how='left') : 기상청은 주말에도 비가 오고 관측을 하지만, KAMIS 도매시장은 주말에 쉬어서 가격 데이터가 없음. 이걸 억지로 교집합(inner)으로 합치면 주말의 날씨 데이터가 통째로 날아감.
	--> 날씨를 기준(left)으로 합치고, 가격이 없는 날은 빈칸(NaN)으로 남겨둬야함.
